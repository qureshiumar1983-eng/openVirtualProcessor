Getting started

Show the welcome screen (the short first-run intro; opening it again doesn't change anything)

Run a program in five steps. Everything below starts from the main page, the Console.

  1. Click a row in Program slots to pick the slot (1–10) you want to use.
  2. Click the file chooser and pick your program: a .cpz or .dll (SIMPL# Pro), a .lpz (compiled SIMPL Windows) or a .smw. For a .lpz, select its .sig too (Ctrl+click) so signals have names. In the desktop app you don't need to: OpenVP finds the .sig next to the program by itself.
  3. Click Load & start. The slot's state turns to Running, and messages from the program appear in the Log.
  4. In the IP table, click a row and then open test panel to press buttons on that IP ID from your browser.
  5. Click Open debugger ↗ to watch the program's signals change live.
Most buttons also show a short description when you hold the mouse over them. Every page has a Help link at the top that opens this page at the right section.

Console (main page)

Load programs, see who is connected, manage the program's files, and read its log. Everything on the page is about the slot selected in Program slots.

Internet access

The bar under the title. Lets people outside your network open the panels you share.

The switch
Turns Internet access on or off. When on, OpenVP runs cloudflared, which makes a free Cloudflare "quick tunnel" (no account) and gives it a public https://….trycloudflare.com address. Only shared-panel links work through it. The console, the API and the debugger can't be reached from the internet. It is off every time OpenVP starts.
The status
starting while cloudflared starts, on when the address is ready (it can take a few seconds before it answers), error with the reason if something went wrong or cloudflared stopped, off when it is off. cloudflared output shows its recent messages.
The address · Copy
The public address while the tunnel is on. While it is on, new share links use it. The address changes each time the tunnel starts, so links you copied earlier need the new address.
Stop
Turns the tunnel off and kills cloudflared. Everyone outside is cut off at once.
Download cloudflared and start
Shown the first time, if cloudflared isn't installed. OpenVP downloads Cloudflare's official build from github.com/cloudflare/cloudflared into its data folder (tools), only after you click this. Cancel downloads nothing. If you'd rather install cloudflared yourself, put it on the PATH or set OpenVP:CloudflaredPath.
Not for XPanel
Classic VT Pro-e XPanels and the Crestron apps connect over CIP (port 41794), and Crestron Virtual Panel over a secure WebSocket on port 49200; neither can go through the tunnel. Browser panels and CH5 projects can.

Status board

A tile
One per slot, across the top of the page, so you can see every slot without clicking into it. A tile shows the slot number and Room ID, the program and its kind (or "empty"), the state (green dot for Running, amber for Stopped, red for Error, dim for empty), how many of the slot's IP IDs have a panel online, and events per second. Click a tile to select that slot, the same as clicking its row below. The selected slot's tile is highlighted. The board refreshes every 2 seconds.
problem
A red badge on a tile. Hover it to read what's wrong. It shows when the slot is in the Error state or when Metrics lists a problem for it: the slot thread stuck in one event, events backing up, a thread left running from an unloaded program, or background work running for 30 s or more.
Name and colour
A slot can have a friendly name and a colour (Slot settings). The name shows on the tile, in the slot table, in page titles and in the debugger and metrics headers; the colour is a stripe.
The tick box · bulk actions
Tick the boxes on tiles (or in the Program slots table) and a bar appears with Start, Stop, Restart and Unload for all ticked slots. Stop, Restart and Unload ask once. After an Unload you can undo it for a few seconds.
↻ restart · ↯ crashed
The slot's crash policy, and what it last did (when, and whether it restarted or stopped). See Slot settings.
auto-reload
A blue badge on a tile whose program reloads when its file changes. Hover it to see the file.
● recording ▶ replaying
A red or blue badge on a tile while that slot is recording, or while a recording is being replayed into it. See Recordings.

Program slots

A row in the table
Click it to select that slot. The rest of the page (IP table, files, console, log) switches to it. The State column shows Running, Stopped, Error or empty.

Slot

Everything for the selected slot is in the bar at the top of the page, and it shows only what fits that slot. An empty slot shows three steps (pick a slot, choose its program file, click Load & start) with the buttons to load a program. Once a program is loaded, the bar shows Open debugger, the panels and Start / Stop / Restart / Unload; the load buttons, Inspect .lpz, Compatibility, Room ID and Lock slot… fold behind More ▾. Slot settings stay in the Slot box below.

Drop a program
Drop a .cpz, .dll, .lpz or .smw (with its .sig and sidecar files) anywhere on the page and it loads into the selected slot. The overlay names the slot. In the desktop app it loads from where the file is on disk, like Load & start. Dropping on the Files list still uploads there.
Recent ▾
The last 10 programs loaded. Click one to load it into the selected slot. A program loaded from a path is loaded from that path again; an upload is loaded from the copy OpenVP kept (up to 100 MB each).
Choose files
Picks the program file(s) from your computer. Nothing is loaded until you click Load & start; OpenVP tells you whether the program will run, see Will it run?. You can select several files at once, for example a .lpz with its .sig.
Load & start
Uploads the chosen file(s) into the selected slot and starts the program. It replaces whatever was in the slot before. In the desktop app it loads the program from where it is on your computer instead, and brings along the files that belong with it: the .sig with the same name (or the only .sig in that folder), the .lpz behind a .smw, and sidecar files like .openvp.json. The Log lists what came along.
Reload when the file changes
Shown in the desktop app, or when the page is open on the OpenVP computer itself. When ticked, a program loaded from your computer is loaded again by itself whenever its file (or its .sig) changes, for example each time you compile in SIMPL Windows. OpenVP waits until the compiler has finished writing. A running program starts again; a stopped one stays stopped. Your choice is remembered.
Load from path…
Shown when the page is open in a browser on the OpenVP computer itself (a browser can't tell OpenVP where a chosen file is). Type or paste the program's full path, for example C:\Programs\Room\Room.lpz; its .sig and sidecar files come along as above.
Reloads when this changes · Stop watching
Shows which file the slot is watching. Stop watching keeps the program running but stops reloading it. Loading another program, or Unload, also stops it.
Try the demo
Loads two samples into slots 1 and 2 and opens a panel, see Try the demo.
Inspect .lpz
Reads the chosen .lpz without running it and prints a report in the Console box: what's in it and which parts OpenVP can and can't run. Add the .sig to see signal names.
Start
Starts the program loaded in this slot, after it was stopped.
Stop
Stops the program but keeps it loaded, so Start runs it again.
Restart
Loads the program again from its file and starts it.
Unload
Stops the program and removes it from the slot. The slot becomes empty. Files in NVRAM and User are kept. A snapshot is saved first, so Undo (shown for 10 seconds) puts the program back.
Compatibility
Prints a report in the Console box listing anything the loaded program uses that OpenVP doesn't support yet. Check this first if a program misbehaves.
Room ID Edit…
Changes the slot's Room ID (the Virtual Control "room" name). Panels can connect to the slot by this name instead of its number. Shown only when the slot has a Room ID.

Will it run? (readiness check)

As soon as you choose a program file, or drop one on the page, OpenVP reads it without loading it and says whether it will run. It never stops you from loading: it is advice.

✓ Will run
Green. Everything the program uses is supported.
! Will partly run, N things aren't supported yet
Amber. The program loads and runs, but it uses symbols, SIMPL# types or SIMPL+ modules OpenVP doesn't have yet. Open the list to see them: those parts do nothing, and the rest works. The same things are in the Compatibility report once the program is loaded.
✕ Won't run
Red, with the reason: the file isn't a program, it is damaged, or a .dll has no CrestronControlSystem class to start.
Dropping a file
A box names the slot and shows the verdict, with Load & start and Cancel. Load & start is always available, whatever the verdict.
How it checks
It loads the program into a throwaway one-slot processor that is never started, so nothing runs, no panel registers and your slots are untouched. For a file on this computer (desktop app) the .sig and sidecar files next to it are used too. Inspect .lpz still prints the long report.

Program summary

One plain sentence about what is in the program, for example SIMPL Windows · 3 touch panels (IP IDs 03, 04, 05), 2 EISCs, 4 COM ports, 1 IR port, 12 SIMPL+ modules, 2 user macros, 1,284 signals.

Under the program name
Shown under the slot's file name once a program is loaded, and in the readiness check before you load it. Hover a tile on the Status board to read it there.
What it counts
Touch panels and XPanels (with their IP IDs), EISCs, other IP devices, COM and IR ports, SIMPL+ modules, user macros and the signals the logic uses. User macros are counted from the compiled .lpz (a .smw alone doesn't show them).
SIMPL# programs
A SIMPL# program makes its devices when it starts, so before then the summary only names the device types it refers to. Once it runs, it counts the devices it registered.

Try the demo

Try the demo
On the Welcome screen, next to Recent ▾ and in the search box (Ctrl K). Loads the SIMPL# Pro sample into slot 1 and the SIMPL Windows sample into slot 2, links them over an EISC, starts both and opens slot 1's test panel. If slot 1 or 2 already has a program it asks first; the replaced program is saved in History.
What to press
On slot 1's panel press digital 10 (the button labelled 10). Slot 2's panel (IP ID 03) lights its button 10, and the other way round. Digital 1 toggles a lamp on the panel you are on.

Templates

Templates · SIMPL# Pro starter
A zip with StarterProgram.csproj, ControlSystem.cs (a panel at IP ID 03 and an EISC at IP ID 10) and lib/. Unzip it, run dotnet build, then load bin/Debug/net8.0/StarterProgram.dll into a slot. It builds against OpenVP's own copy of the SIMPL# Pro API, so it needs no Crestron files; to build for a real processor, point the project's two references at Crestron's SDK.
Templates · CH5 panel starter
A .ch5z web page with buttons (digital joins), a slider (analog join 1) and text feedback (serial joins), using numeric joins. Upload it for an IP ID (Upload .ch5z… in the IP table), then Share…. It also runs as a plain page: unzip it and open index.html?host=localhost:8080&ipid=03&slot=1.

Activity

A processor-wide list of who did what and when, newest first. It is kept in activity.jsonl in the data folder (the last 5,000 entries) and also at GET /api/activity.

Show
All slots, the selected slot, or one slot. Entries about the whole processor (Internet access, templates, the demo) show under all slots.
Who
this computer for something done on the OpenVP computer, an address for another computer, share link … for someone using a shared panel and auto for what OpenVP did by itself (reloads when a file changes, crash-policy restarts, restores at start-up). When OpenVP has user accounts a name will show here too.
What is listed
Loads and unloads, start, stop and restart, roll backs and snapshots, recordings and replays, share links made, opened and revoked, CH5 projects, Internet access on and off, settings changes, crash-policy actions, auto-reloads and start-up restores. The Metrics page shows the latest few.

Slot settings

Under the slot's buttons. Each change is saved as you make it.

Name · Colour
Optional friendly name (up to 40 characters) and colour. Saved in the slot's slot.json next to the Room ID.
Autostart
On (the default): when OpenVP starts, the slot's last program comes back, and is started if it was running. A program loaded from a path comes back from that path (and is watched again if it was); if the file is gone, OpenVP uses the copy it kept. Off: the slot stays empty after a restart. A program in OpenVP:Autoload always loads.
Start order · Delay (s)
Slots come back lowest start order first (ties by slot number). Each waits its delay, in seconds, after the one before it. A slot that fails to come back goes to Error and the others carry on. The log says what was restored.
If it crashes
Stay stopped, Restart, or Restart a few times, then stop (up to N restarts in M minutes). A crash is a running program that faults: an unhandled exception in an event handler (when Unhandled exception = crash is on) or one event running longer than Stuck after (s). A program that fails to load or start is never restarted, so a broken program can't loop. Plain Restart still stops after 10 restarts in a minute. Restarting a stuck slot waits for its stuck thread, up to about 35 seconds.

Search, shortcuts and undo

Ctrl K or ⌘ K
Opens a search box for every action: select, start, stop, restart or unload a slot, open the debugger, paths, metrics or help, open or share a test panel for an IP ID, snapshot, record, Internet access, theme, recent programs. Type a few letters (dbg 3 finds the debugger for slot 3), use the arrow keys, Enter to run, Esc to close.
Keyboard shortcuts
1–9, 0 select slot 1–9 and 10 · S start · X stop · R restart · U unload · D debugger · P paths · M metrics · N snapshot now · L the log filter · F find a signal in all slots · T theme · ? the list. They never fire while you type in a box. In the debugger: F5 stream, Ctrl F5 step mode, F7 back, F8 run, F9 mark, F10 next, S star, N note, Y why is it this value, W watches, ? the list.
Undo
After Unload, deleting a file or folder, changing a Room ID, revoking a share link, or deleting a snapshot or recording, a message with Undo shows for 10 seconds. Deleted files, snapshots and recordings wait in the data folder's trash for 24 hours. A revoked link comes back with the same address and PIN if undone within 10 minutes.
On a phone
Sections collapse (tap a heading), a slot picker with Start, Stop and Restart stays at the top, and tables become cards.

IP table

Every IP ID the program registered (touch panels, EISCs and other devices) and who is connected to each.

A row in the table
Click it to open the details below the table: who the client is, how long it has been connected, and traffic counts.
Re-identify
Tries again to work out what the connected device is (its hostname and model), using reverse DNS and Crestron autodiscovery. Takes a few seconds.
Log in & read…
Shows a small login form. Enter the device's SSH username and password, then click Log in & read: OpenVP logs in to the device and reads its hostname, firmware, uptime, network settings and IP table. It only reads; it changes nothing on the device. The password is used once and never saved.
open test panel
Opens a browser test panel already connected to this IP ID and slot.
Remap IP ID… · Undo remap
In the details. Makes panels reach this program IP ID at a different number without recompiling: type the number it should answer at (two hex digits, like 0A). Panels, shared links and CIP touch panels then connect to 0A and drive the program's own 03; the program still sees 03. The table shows 03 with at 0A under it. While an ID is remapped, panels connecting to its old number reach nothing. A link shared before the remap keeps its old number, so make a new one. Undo remap puts the original number back. The README has the details (IP ID remap).
Share…
On every row of the table and in the details. Opens the Share panel box, see Share a panel below. The link uses the number panels connect to.
Upload .ch5z… · Replace .ch5z… · Remove
In the details. Puts an HTML5 (CH5) project on this IP ID, so shared links open it instead of the test panel. Remove goes back to the test panel. See Share a panel.
✕
Closes the details.

Share a panel

Give someone a link that opens one panel, and only that panel. They can press the buttons on that IP ID. They can't see the console, the debugger, the files or any other slot or IP ID.

Share… box
Choose a Label (only you see it), an optional PIN and when the link Expires, then click Create link. The box then shows the link with a Copy link button and a QR code for a phone camera.
PIN
4 to 8 digits. The person is asked for it before the panel opens. Random fills in a 6-digit one. OpenVP keeps only a scrambled copy, so the PIN is shown once, when you create the link: write it down and send it separately from the link. Five wrong tries from one device lock it out for 5 minutes.
Address in the link
Where the link points. If you opened the console as localhost, that wouldn't work for anyone else, so this lists this computer's network addresses. Pick the one the other person can reach. Links on a network address only work for people on that network. With Internet access on, the first choice is the tunnel's public address, which works from anywhere.
CH5 project
If this IP ID has an uploaded .ch5z, the link opens that. Otherwise it opens OpenVP's own test panel, with the IP ID fixed. The box has the same Upload / Replace / Remove buttons.

Shared panels

The links you have made.

A row
The label, the slot and IP ID, whether it opens a CH5 project or the test panel, when it expires, when someone last opened it, and how many people have it open right now.
Copy
Copies the link.
QR
Shows the link and its QR code again. A PIN can't be shown again: for a new PIN, make a new link.
Revoke
Click it twice. The link stops working and anyone using it is disconnected within a few seconds; their page shows "This link has expired or was revoked".

File editor

Edit a config file in the browser instead of downloading, changing and uploading it again. Line numbers run down the left. Every save writes the file the way it was (same line endings and encoding).

The status line
Shows the line and column of the cursor. For JSON and XML files it checks what you type: valid JSON in green, or the line and the problem in red, and that line number turns red.
Save (Ctrl+S)
Writes the file. The earlier content is kept in the trash, and the Saved message offers Undo for 10 seconds (and in Undo for 24 hours). If the JSON or XML isn't valid, Save says which line is wrong and offers Save anyway.
"This file changed on disk"
Appears when the file was changed (by the program, or by someone else) after you opened it. Reload from disk drops what you typed and reads the new content; Keep my version hides the message. A save over a changed file is refused until you choose Save anyway.
Reload from disk
Reads the file again. It asks first if you have unsaved changes.
Size limit
2 MB. A bigger file can still be downloaded, changed elsewhere and uploaded.

History

Before a new program is loaded into the slot, OpenVP saves a snapshot of what is there: the program files plus the NVRAM and User folders. The last 10 are kept. The Room ID isn't part of a snapshot.

Snapshot now
Saves a snapshot of the slot as it is, without loading anything.
Versions…
Opens Program versions for the slot: every program that was loaded into it, to load again, download, annotate or compare.
Roll back
Puts the slot back as it was at that time: program, NVRAM and User files are replaced, and the program is loaded again (and started, if it was running). The current state is saved first as a "before roll back" snapshot, so you can undo it. It asks you to confirm first.
Delete
Deletes that snapshot (Undo is offered for 10 seconds).

Recordings

Record what a person does to a room, then replay it after loading a new program version and get a PASS or FAIL: does the program still answer the same way? It captures everything coming into the program (panel presses, levels and text, EISC inputs, and signals you force in the Debugger) and the feedback the program sends back.

● Record · ■ Stop
Starts and stops recording the selected slot. While it records, the button shows the time and how many inputs have been captured. Stop asks for a name (Cancel keeps the suggested one, program name and time) and saves the recording. Start recording when the room is in the state you want to test from, for example right after loading the program. A recording also ends, and is saved, if the program is unloaded or replaced meanwhile.
Replay
Sends the recorded inputs into the slot's program with the same gaps between them (so timers and delays behave as they did), then compares the feedback with the recording. A bar shows progress; Cancel stops it and gives no result.
Replay fast
The same, but a gap between inputs longer than 1 second is shortened to 1 second. Shorter gaps stay as recorded, because programs often depend on press and release timing. The program's own timers still run in real time, so use Replay for programs that depend on long delays.
include EISC inputs
Also sends the inputs that came in over an EISC link from another slot. Turn it off if that other slot is running and drives the EISC itself while you replay. The result notes which you used.
PASS / FAIL and the table
PASS (green) means every recorded feedback change came back with the same value near the same time, and each device ended in the same state. FAIL (red) lists each difference: the device (IP ID), join, expected value, actual value, and the time in the recording where it was expected. Warnings (extra feedback that wasn't recorded, or a different starting state) are listed apart and don't change the result. Result shows the latest result of a recording again.
Download · Upload
Save a recording as a file to keep with a project or share, and add one back (to any slot).
Rename · Delete
Rename a recording, or delete it with its results (no confirmation; Undo is offered for 10 seconds).
● recording · ▶ replaying
Badges on the slot's tile in the Status board.
⚠ oscillating · exceptions
Badges on the slot's tile: a signal that races or oscillates (when detection is on in the debugger's Alerts panel), or unhandled exceptions thrown by a SIMPL# program. Hover for the first one.

Log

The log box
Messages from OpenVP and the program in this slot. Errors are red, warnings yellow, notices blue, info and console output plain.
Error Warning Notice Info buttons
Each shows how many lines of that level the log holds. Click one to hide or show those lines (the choice is remembered). Console appears when the program printed to the console.
Search box L
Shows only lines containing the text (case does not matter). Esc clears it.
Pause / Resume
Stops the list moving while you read. New lines are kept and added when you resume.
Copy Download
Copy the lines now shown (after the level buttons and the search) to the clipboard, or save them as a text file.
Links in a line
A signal name, or a SIMPL# join such as IPID03.out.d1, opens the slot's debugger on that signal: the search is set, the row selected and scrolled into view (a debugger window already open for the slot is reused). IP ID 03 jumps to that row of the IP table, slot 2 selects the slot, and a program path such as \USER\config\rooms.json shows that folder in Files. Other file paths are copied when clicked.
▸ in front of a line
Lines that carry more text, such as the stack trace of an exception, expand when you click it.
SIMPL+ source ↗
Opens splus.html?slot=N: the program's SIMPL+ modules, and the source (.usp, and .usl, .inc, .h includes) with highlighting and line numbers. OpenVP looks next to the program (pick the .usp files along with it when you load it) and in the source archive inside a compiled .lpz. A frame of an exception that points into one of these files is a link to that line. Anyone who can download the program's files (a Viewer or above) can read it; it is not available on the internet tunnel.
Full page ↗
Opens the log for this slot on its own page (log.html?slot=N) with the same buttons and an Exceptions tab; it also works on a phone.
Exceptions (n)
Under the log, when a SIMPL# program has thrown an exception that nothing caught: in an event handler, a CTimer, a CrestronThread or CrestronInvoke. Each shows its type, message and what was running, and expands to the stack frames with file and line when the program's .pdb was found (put it next to the .dll or inside the .cpz; it must be a portable PDB, which is what dotnet build writes). Full text has the complete trace.
Support bundle…
Downloads a zip to send when asking for help: the slot's log, the recent trace (if a debugger was open on the slot), the compatibility report, program summary, metrics, slot settings, the slot's activity, its exceptions and watches, and the OpenVP version and OS. It never contains the access key, and leaves out the program, NVRAM and User files unless you tick Include the program files.
− + Maximize
Same as for the Console box: shorter, taller, fill the window.

Find a signal in all slots

Box in the top bar F
Type part of a signal name (at least two letters; several words must all appear, * matches anything). It lists matches from every loaded slot with their value; pick one to open that slot's debugger on the signal. The command palette (Ctrl K) lists the same matches as Signal: name.

Devices

Open it with Tools → Devices in the console's top bar. Everything on it is for the slot chosen at the top. It helps you test a program without its real devices: fake devices that answer, a window on the COM ports, a list of the program's sockets, and a way to point a device's address at a fake one.

Simulators

Fake devices that answer a COM port or a TCP/UDP connection with canned replies. The profiles are generic, made-up protocols, not any maker's; edit the rules to match your device.

New simulator…
Pick a profile (generic projector, display, DSP or video switcher), a name, and what it attaches to: a COM port of the program (choose one the running program has opened, or type its name like COM-01 or IP-ID-11/Slot-08/COM-01), or a local TCP or UDP port on 127.0.0.1 that the program connects to (0 picks a free port).
The status
port open, answering: the program has the COM port open. waiting for the program to open the port: load and start the program. listening on 127.0.0.1:N: a TCP or UDP simulator is ready. An error (such as the port being in use) is shown in red.
The state boxes

Integrations

Open it with Tools → Integrations in the console's top bar. It connects slots to other systems: MQTT and Home Assistant, webhooks, OSC, Art-Net and Prometheus. The slot chosen at the top decides which signals you pick; the connection settings (broker, ports) are for the whole of OpenVP. Every change is written to the Activity feed. MQTT

Publishes chosen signals to an MQTT broker and lets the broker set them. The bridge uses its own thread and a limited queue, so a slow or dead broker never holds up a program; if the queue fills, the oldest changes are dropped and counted.

Broker, port, TLS, user name, password
Where to connect. The password is kept in a file only you can read (encrypted for your Windows account on Windows) and is never sent back to this page; leave the box empty to keep it, or tick Remove the saved password.
Client id · Base topic
Both have defaults from this computer's name (openvp-<host> and openvp/<host>), shown greyed in the boxes.
Topics
<base>/status is online or offline (the broker sets offline if OpenVP dies). <base>/slotNN/state is running, stopped, loaded, empty or error. <base>/slotNN/<signal> holds the value (retained). Letters, digits and _ . - stay as they are in a signal's topic; every other character becomes _.
Add signals…
Pick from the slot's signals. Set lets …/set change the signal: 1, 0, true, false or pulse for digital, a number or 50% for analog, any text for serial. Only signals with Set ticked are subscribed. Retained messages on a /set topic are ignored.
Home Assistant discovery
Turn it on above and tick Home Assistant for a signal: a digital signal becomes a switch (a binary sensor if it can't be set), an analog one a number (a sensor if it can't be set) and a serial one a text sensor. Turning it off for a signal removes the entity.
The status
Connected, connecting or error (with the broker's reason), the number of signals, messages in and out, how many were dropped, and when the last one went.

Webhooks

Outgoing webhooks send a request when something happens in a slot. Incoming webhooks let another system set signals.

New webhook…
A URL, and either When a signal changes (every change) or When a condition becomes true, written in the watch language: Room_On=1 && Proj_Power=0 for 2s. Check tells you whether it reads and which signals the program doesn't have. A condition sends once each time it becomes true. Optional headers (Name: value per line) and a signing secret.
The request
A POST of JSON: event (signal.change, expression.true or test), time, slot, room, program, webhook, and signal, kind and value (or expression and values). With a secret, X-OpenVP-Signature is sha256= and the hex HMAC-SHA256 of X-OpenVP-Timestamp + "." + body.
Retries and the log
A request that fails (no answer within 10 s, a network error, 5xx, 408 or 429) is tried again after 1 s, 5 s and 30 s. Other 4xx answers are not retried. The Delivery log lists each delivery with its result, tries and time. Each webhook has its own queue, so a slow one only delays itself; when 200 are waiting the oldest are dropped.
Test
Sends a sample event now (once, no retries) and shows the result in the log. It is marked test.
New incoming webhook…
Makes an address like /hooks/<token> for one slot, optionally limited to the signals you list. Send POST with {"signal":"Room_On","value":1} or {"pulse":"Button1"}. Values follow the same rules as MQTT. It works without the access key, because the token is the key, and is not available through the internet tunnel. Switch off pauses it; Revoke deletes it and the address stops working at once. A hook is limited to 20 requests per second (a burst of 40), and an address that tries more than 10 wrong tokens a minute is refused.

OSC

Open Sound Control over UDP.

Listen on UDP port
0 turns listening off. Messages to /openvp/slotNN/<signal> set signals ticked Receive; others are ignored and counted as refused. Digital: an int (non-zero is high), a float (above 0.5 is high), true or false, no value to pulse, or /pulse on the end of the address. Analog: an int 0-65535, or a float from 0 to 1 as a fraction of full scale. Serial: a string.
Send to
A host and port. Each change of a signal ticked Send goes there as one message to the same address (digital and analog as an int, serial as a string). An empty host turns sending off.

Art-Net

Analog signals as DMX channels.

Send to · Frames per second
One ArtDMX packet per universe in use is sent at the chosen rate (1 to 44) all the time, as DMX nodes expect, whether or not anything changed. Use a node's address or a broadcast address.
Add signals…
Each signal gets a universe (0 to 32767), a channel (1 to 512) and 8 or 16 bits. 8-bit scales 0-65535 to 0-255. 16-bit sends the high byte on the channel and the low byte on the next one. A digital signal is 0 or 255. Two signals can't share a channel.
Receive
Tick Also receive ArtDMX and Receive on a channel: incoming ArtDMX on UDP 6454 for that universe sets the signal when the channel's value changes.

Schedules

Open it with Schedules ↗. Times are the processor's local time zone (shown at the top) and follow daylight saving. A time that doesn't exist on the day the clocks go forward (02:30 when 02:00 jumps to 03:00) runs once, just after the gap. A time that happens twice when the clocks go back (01:30) runs the first time, except a schedule that runs every hour or every few minutes, which keeps running through the repeated hour.

New schedule…
Name it, choose what it does, and when. Actions: restart a slot (load its program again and start it), start, stop, load a program version into a slot, load a program file from this computer (only when you set it up on this computer), set a signal to a value, pulse a digital signal, or back up the processor. When: once, every day, on certain days of the week, or advanced (a cron expression: minute hour day-of-month month day-of-week, with lists, ranges, steps and day or month names). The next few run times are shown as you type.
Run it once if OpenVP wasn't running
If OpenVP was stopped (or the computer asleep) at the time, a schedule with this ticked runs once when OpenVP starts, as long as the missed time was within 24 hours. Otherwise the missed run is skipped and the history says so. Several missed times are one run.
On
Turns a schedule off without deleting it. Turning it back on doesn't catch up on what it missed.
Next run · Last run
When it will run next, and how the last run went (hover for the message). A one-off shows done after it has run.
Run now
Runs the action now, whatever the time.
Run history
The last runs with their result: ok, failed (with the reason) or skipped (missed, or the previous run was still going). A failed run raises a schedule.failed alert. Every run is in the Activity feed as auto.

Push to other machines

Add target…
A name, the other server's address (http://192.168.1.20:8080) and its access key. The key is kept in the secret store and never shown again; leave it empty when editing to keep it. Save and test connects and checks that the key is accepted.
https targets
The certificate is checked. For a self-signed certificate, Fetch certificate shows its fingerprint (SHA-256); compare it with the other machine's, and saving it makes OpenVP accept only that one certificate for this target. A program version

Sends a fresh export (the slots you tick) and imports it on each target as Import would. Tick replace the target's processor settings to send those too, and include secrets to send them encrypted with the password (the target restores them with it).

One row per target with its state (queued, running, ok, failed) and what happened in each slot. Targets run at the same time; one failing doesn't stop the others. Pushes are written to the Activity feed.

Choose which kinds of alert (none ticked means all), which slots (empty means all), the minimum severity, and the channels. An alert goes once to every channel named by every rule it matches.

Switches one off without deleting it.

Reports tab

Send it on a schedule
Every day or every week at the time you set, through the ticked channels. Turning it on doesn't send for a time that has already passed.

Sends the last 24 hours or 7 days through the ticked channels and shows the result for each.

Opens or saves the report as a web page: uptime for each slot, crashes and restarts, alerts, the most frequent events, devices that dropped, peak CPU and memory, and programs loaded or changed.
