What each role can do

Admin
Everything, including users, tokens, HTTPS, single sign-on, the audit log, export and import, backups, push targets and the internet tunnel.
Programmer
Load, unload and roll back programs, the debugger, files, recordings, snapshots, simulators, a slot's integrations and schedules, plus everything a Technician can.
Technician
Start, stop and restart, panels and signals, the IP table, shared links, acknowledging alerts, locking a slot, and viewing everything.
Viewer
Read-only.

A user limited to some slots only sees and changes those. The server checks every request; the buttons you can't use are only dimmed for your convenience.

API tokens

For scripts and for other OpenVP machines that push to this one. Send a token as Authorization: Bearer ovp_… or X-OpenVP-Key. Only a hash is kept, so the value is shown once, when you make it.

HTTPS

These settings take effect after OpenVP restarts (the listening port is chosen at start-up). Replacing the certificate needs no restart.
Download certificate (.cer)

A self-signed certificate covers this computer's name, openvp.local, localhost and its network addresses. Browsers warn about it until you trust it: download the .cer and add it to the machine, or compare the fingerprint above when the browser shows it.

Listen on HTTPS

The redirect never touches this computer, the API, WebSockets, webhooks, /healthz, shared panels or CIP.

The desktop app keeps using http://localhost. Shared-panel links use https once it is on.

Let's Encrypt optional

A free public certificate by ACME HTTP-01. It needs a public host name that points at this machine, and Let's Encrypt must reach port 80 on it (forward port 80 to OpenVP's http port). Off unless you click Get certificate. Not for a machine that is only on a private network.

Claim to role

If several match, the highest role wins. Role and slots are re-read at every sign-in; edit a single-sign-on user's slots under Users.

Requests from this computer

On by default so the desktop app, which opens http://localhost:8080, keeps working without a login. The trade-off: anyone who can sit at this computer, or run a program on it, is an Admin. Turn it off on a shared or remote machine; then everyone, here too, signs in or sends the access key. It never applies to requests that came through a proxy or the internet tunnel. OpenVP:LocalRequiresKey=true switches it off for good, before any user exists too.
